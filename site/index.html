代码嵌合的三处落地

手法解决什么效果
X-macro 表驱动 枚举与字符串/数值表必须一致，手写必然漂移 一张表定义一次，同时展开为 enum + 名称表 + 数据表；_Static_assert 校验长度
一份逻辑 + 两份数据 A股/美股制度差异会导致复制两份实现，各自演化 CN/US 共用全部算法，差异收敛到 market_profile_t 数据剖面
统一评估结构 四个分析模块各写一套返回结构，信号层要写四套适配 四个模块返回同一个 assessment_t，信号与建议层只处理一种结构

同步审查流程四道闸门

每个模块写完立即跑闸门，通过才进下一个。make check 一次跑完全部四道。

闸门检查什么开发中实际拦到的问题
G0 编译期 -Wall -Wextra -Werror -Wpedantic -Wshadow -Wconversion + _Static_assert ① const char *const * 与 const char ** 不兼容
② 未使用的静态函数 put()
③ 未使用的变量
④ 枚举计数名写错（ACT_COUNT vs action_COUNT）
G1 静态分析clang --analyze 数据流与空指针—
G2 单元测试 制度数值、时效纪律、决策分支、硬约束 ① 缺口判定写死阈值导致检查项少的模块带分通过
② 0 连跌停时最坏损失算成 0
G3 集成测试跨模块一致性壁垒模块评分与发现自相矛盾（99 分「宽」vs 发现写「存疑」）
为什么闸门必须自动化：上面这些问题没有一个是"代码跑不起来"。 它们全部能编译、能运行、能出结果 —— 只是结果悄悄是错的。 靠人眼看代码发现不了，靠运行也发现不了，只有类型系统和断言能。

快速开始

# 构建
make all

# 跑完整审查（G0 编译期 + G1 静态分析 + G2 单元 + G3 集成）
make check

# 运行演示
./build/cqs 002422
