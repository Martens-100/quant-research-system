## cqs · C 语言量化投研系统

### 设计取向

**先约束自己，再分析市场。** 把规则写成可执行的代码，从而暴露规则本身的矛盾。

| 问题 | 本系统的应对 |
|---|---|
| 规则含混 | 决策树穷举分支，未覆盖的组合显式报错 |
| 数据脱钩 | `field_value_t` 强制携带取数时刻与交易状态 |
| 制度缺位 | `rules` 模块重算最坏损失，反推仓位 |
| 信号打架 | 五级优先级 + 可审计判定链 |

### 模块分组

依赖方向严格单向，禁止回指：

```
core    领域模型            <- 无依赖
rules   制度约束            <- core
data    字段时效            <- core
signal  三层指标 + 三级信号  <- core, data
risk    风控                <- core, rules
analysis 四模块 + 建议映射   <- core, signal
main    CLI                 <- analysis
```

### 代码嵌合的三处落地

| 手法 | 解决什么 |
|---|---|
| **X-macro 表驱动** | 枚举与字符串/数值表必须一致，手写必然漂移。一张表定义一次，同时展开为 enum + 名称表 + 数据表，`_Static_assert` 校验长度 |
| **一份逻辑 + 两份数据** | A股/美股制度差异会导致复制两份实现。CN/US 共用全部算法，差异收敛到 `market_profile_t` |
| **统一评估结构** | 四个分析模块返回同一个 `assessment_t`，信号与建议层只处理一种结构 |

### 快速开始

```bash
cd cqs
make all          # 构建
make check        # 四道闸门：编译期 + 静态分析 + 单元 + 集成
./build/cqs 002422
```

### 四道审查闸门

每个模块写完立即跑闸门，通过才进下一个。

| 闸门 | 检查什么 | 实际拦到的问题 |
|---|---|---|
| **G0** 编译期 | `-Wall -Wextra -Werror -Wpedantic -Wshadow -Wconversion` + `_Static_assert` | `const char *const *` 类型不兼容；未使用的函数/变量；枚举计数名写错 |
| **G1** 静态分析 | `clang --analyze` | — |
| **G2** 单元测试 | 制度数值、时效纪律、决策分支、硬约束 | 缺口判定写死阈值；0 连跌停时最坏损失算成 0 |
| **G3** 集成测试 | 跨模块一致性 | 壁垒模块评分与发现自相矛盾 |

> 这些问题**没有一个是"代码跑不起来"**。它们全部能编译、能运行、能出结果 ——
> 只是结果悄悄是错的。靠人眼看代码发现不了，靠运行也发现不了，只有类型系统和断言能。

## 关键结论

来自真实数据（002422 科伦药业，2026-10-08）：

- **45.44 元**是 2026-08-07 的收盘价，距取数日 62 天，超出价位类 1 天上限 → 拒绝用于决策
- **"38.52 → 45.44 涨 18%"** 两点间隔 37 天 → 跨时点拼接，拒绝计算
- **连续 3 跌停**：计划损失 54,400 元 → 实际 123,142 元，**放大 2.26 倍**，风险预算公式失效
- **仓位折减**：标准法 8.18% → 制度修正版 3.64%，**折减 55.5%**
