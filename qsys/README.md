# qsys · A股 / 美股双市场量化投研系统

按五步法组织的一套**可运行**的研究与风控骨架。设计取向是**先约束自己，再分析市场**。

> ⚠️ **本系统不产生买卖建议。** 它的作用是把规则写成可执行的代码，从而暴露规则本身的矛盾。
> 演示数据来自 2026-10-08 的真实取数，仅用于验证逻辑。

---

## 为什么需要它

原框架是五步法的自然语言描述。自然语言描述有三个无法自证的问题：

| 问题 | 表现 | 本系统的应对 |
|---|---|---|
| 规则含混 | "跌破 40 元且 3 日未收回"—— 谁数这 3 天？停牌日算不算？ | 决策树穷举分支，未覆盖的组合会显式报错 |
| 数据脱钩 | "45.44 元"被当作当前价，实际是两个月前的收盘价 | `FieldValue` 强制携带取数时刻与交易状态 |
| 制度缺位 | 风险预算公式假设止损必然成交，但连续跌停时卖不出去 | `rules/cn.py` 重算最坏损失，反推仓位 |

### 术语约定（重要，避免歧义）

| 术语 | 代码字段 | 含义 |
|---|---|---|
| **三层指标** | `indicator_layer` | 基本面 / 技术面 / 资金面 —— 按**信息类型**划分 |
| **三级信号** | `signal_tier` | 趋势 / 动量 / 极值 —— 按**决策用途**划分 |

两者正交：技术面层（指标）同时供给趋势级与动量级（信号）。
早期版本两处都叫"三层"，会造成歧义，已在代码中区分。

## 七条设计决策及其理由

### 1. 制度约束是一等公民，不是注释

`rules/cn.py` 存在的理由：风险预算公式在制度约束下失效，**且失效方向永远是坏的**。

```
标准法: 100 万资金 / 1% 风险 / 入场 45.44 / 止损 40.00  ->  1800 股（8.18%）
修正法: 同样参数，考虑连续 3 个跌停                      ->   800 股（3.64%）
```

折减 55.5%。若忽略制度约束，实际风险敞口将超出预算 125%。

### 2. 字段必须携带时间戳

`FieldValue` = 值 + 取数时刻 + 交易状态 + 来源 + （财务字段的）公告日。

裸 float 会丢失时间信息，而时间信息是判断数据能否用于决策的**唯一依据**。
实测：同一字段 11:24 取数得 39.36、11:28 得 39.26 —— 因为当时 A 股仍在交易中。

### 3. 数据缺口必须抛错，不得填 0

`DataGap` 异常。静默填 0 会把"没取到"误读为"值为零"，这是最危险的一类 bug ——
它不报错，只让结论悄悄变错。

### 4. 指标输出三态，不输出裸数值

裸数值会诱发"42.61 到底算好还是坏"的伪精确讨论。
三态（多头/中性/空头）直接对应决策，且强制你定义阈值。

### 5. 趋势级有否决权

趋势级为空头时，动量级金叉不构成入场信号。

**这个规则的代价必须说清楚**：趋势级是慢变量，从空头转多头时价格往往已涨一段，
系统会**系统性右侧晚入场**。这是"用收益换确定性"的交易，不是免费的优势。
`SignalEngine.tradeoff_note()` 里有完整声明。

### 6. 逻辑止损优先于价格止损

价格止损回答"我亏了多少"，逻辑止损回答"我为什么买它还成立吗"。
前者是结果，后者是原因。原因不成立时继续等反弹，本质是在赌运气。

### 7. 参数分白名单与黑名单

- **可调**（适应市场）：止损宽度倍数、信号衰减窗口等
- **固定**（约束你自己）：单笔最大损失、扣非门槛、回撤熔断线

如果连"单笔最多亏多少"都能在回测里优化，优化出来的结果一定是最激进的那个。

## 关键结论（来自演示）

| 项目 | 结果 |
|---|---|
| 45.44 元时效 | 距取数日 **62 天**，超出价位类 1 天上限 → 拒绝用于决策 |
| "38.52 → 45.44 涨 18%" | 两点间隔 37 天 → 跨时点拼接，**拒绝计算** |
| 连续 3 跌停最坏损失 | 计划 54,400 元 → 实际 **123,142 元**，放大 **2.26 倍** |
| 仓位折减 | 8.18% → **3.64%**（折减 55.5%） |
| 科伦药业筛选结果 | 成长池与反转池**均未通过** → 排除池 |
| 资金结构评级 | 背离（但拥挤度阈值待校准，故不出结论） |
| 纪律分 | 未执行硬止损 → **0 分**，建议系统接管下单权限 |
| 逻辑分 | 3 条假设 2 条被证伪 → **触发逻辑止损** |
| 情绪分 | 2 次记录均不一致 → **建议暂停交易** |

## 待填项（P0，阻塞全部）

系统可以运行，但**有 9 项输入缺失**，缺了它们后续全是空转：

```yaml
personal_constraints:
  total_capital:                      # 总资金规模
  max_loss_per_trade:                 # 单笔最大可承受损失
  max_drawdown_circuit_breaker:       # 总回撤熔断线
  max_position_per_symbol:            # 单标的最大仓位上限（原设 8%–12%）
  max_concurrent_positions:           # 最大同时持仓数
  holding_horizon:                    # 持有期限
  trading_permissions:                # 交易权限（融资/做空/科创创业/ST）
  actual_trading_cost:                # 实际佣金/过户费/滑点（从对账单取）
  max_consecutive_limit_down:         # 持仓标的历史最大连续跌停天数
```

另有一项**非输入类**的 P0：

> **确认 2026-08-24 与 2026-09-29 两次动作是否执行。**
>
> 这不是准备工作，而是整个系统的第一个数据点：
> - 两次都执行 → 问题在参数（止损太紧被洗盘）
> - 两次都没执行 → 问题在权限（人比系统更容易手软），要改执行机制而非参数
>
> **这两种情况下，后续所有调整的方向是相反的。**

## 已知局限

1. **演示数据内嵌，未接真实数据源。** `data/` 只有抽象接口，akshare adapter 待实现。
2. **回测引擎未实现。** T+1 与涨跌停的建模规则已定义（`rules/cn.py`），但尚未接入回测循环。
3. **拥挤度阈值待校准。** 原值来自单样本，已撤回；校准前该维度不出结论。
4. **交易日历未接入。** `can_sell()` 用自然日做保守近似，未剔除周末与节假日。
5. **情绪分与逻辑分依赖手工输入。** 四维中只有纪律分可全自动 —— 这决定了系统的自动化上限。
