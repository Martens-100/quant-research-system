手动输入型股票分析系统 · 规格说明

输入股票名称 → 四维分析 → 个股研报 → 三类信号 → 操作建议 → 双向复盘
版本 v1.0  ·  生成 2026-10-08  ·  实现：qsys/src/qsys/analysis/（5 个模块，97 个测试全部通过） ·  演示标的：002422 科伦药业（真实取数数据）

零、整体流程

系统采用手动输入而非自动推荐。这个选择决定了两个设计后果：解析必须防猜错，分析必须可审计。

STEP 1
输入名称
解析为代码，置信度不足则拒绝执行
→
STEP 2
四维分析
研报 / 行业 / 现金流 / 壁垒
→
STEP 3
个股研报
结构化字段 + 发现 + 缺口 + 警示
→
STEP 4
三类信号
监控 / 量化 / 多因子
→
STEP 5
操作建议
按优先级映射，附判定链
→
STEP 6
复盘
执行 / 未执行双向
为什么"手动输入"是个关键约束：自动推荐系统可以容忍标的解析错误（反正会推荐很多个）；手动输入不能 —— 猜错一个标的，后面所有分析都会基于错误的公司。因此解析器在置信度低于 85% 或存在近似候选时，会直接中止并要求人工确认，而不是"猜一个最像的"。

一、四个分析模块的输出结构统一结构，便于信号层同构处理

四个模块返回同一个数据结构 ModuleOutput。统一结构的目的是让信号层不必为每个模块写适配逻辑。

字段类型含义
modulestr模块名（研报分析 / 行业分析 / 现金流分析 / 核心壁垒）
scorefloat0–100 分。缺口过多时返回 0 并标记不可用 —— 宁可说"数据不足"，也不给半截数据算出的分数
gradestr等级。研报/行业/现金流用 A/B/C/D；壁垒用 宽/窄/无
fieldsdict结构化字段，供研报与信号层消费
findingslist关键发现（人读）。每条必须是可证伪的陈述，不是形容词
gapslist数据缺口。必须显式列出，缺口字段不得进入决策
caveatslist警示。如"研报为非一手来源，需核实原文"

模块 A · 研报分析

回答的问题：市场已经定价了什么？预期差在哪？

字段计算 / 含义判据与警示
upside_pct(一致目标价 / 现价 − 1) × 100—
target_spread_pct(最高目标价 − 最低目标价) / 均值 × 100>80% 说明卖方未收敛，一致预期不可靠
rating_buy_pct近 6 个月买入/增持占比≥95% 时扣分 —— 全体一致意味着该信号失去区分度
coverage_count覆盖机构数<5 家时样本过小，代表性弱
eps_cagr_pct预测 EPS 年化增速—
has_site_visit是否有机构调研记录无调研时研报可能是基于公开信息推演
固定警示：研报属非一手来源，引用需核实原文，不得与公司公告同等处理

模块 B · 所属行业

回答的问题：这家公司在它自己的赛道里排第几？
为什么不能跳过：毛利率 47% 在医药是常态、在零售是异常。脱离行业谈估值无效。

字段取值评分映射
lifecycle_stage导入 / 成长 / 成熟 / 下行60 / 90 / 65 / 25
company_position龙头 / 细分龙头 / 追赶者 / 边缘95 / 80 / 55 / 25
competitive_intensitylow / medium / high85 / 65 / 40
industry_margin_trendup / flat / down85 / 60 / 30
industry_revenue_growth行业中位营收增速 %±15 分内线性加减
relative_strength_60d相对行业指数强弱 %±10% 为显著
sector_flow板块资金 in / out / neutral辅助字段

模块 C · 现金流

回答的问题：利润是真的吗？
这是四模块里最能识别"纸面利润"的一个。实证：科伦药业 2026H1 归母 +12.71% 而扣非 −29.03%。

字段计算判据
现金含量经营现金流净额 / 归母净利<0.8 时判定"利润未有效转化为现金"
自由现金流经营现金流 − 资本开支为负 = 扩张期特征，但需确认开支能形成未来收益
经营现金流序列近 3 期趋势连续改善 / 连续恶化
有息负债/经营现金流有息负债 ÷ 经营现金流>3 年偿债压力偏高
应收/营收应收 ÷ 营收 × 100>50% 提示增长可能靠放宽账期换取

模块 D · 核心技术壁垒

回答的问题：说出壁垒是什么，说不出就是没有。

硬约束（两条，都会强制降级）：
① moat_source 为空 → 无论其他字段多好看，等级强制为「无」，得分 10。理由：壁垒必须可命名，说不出就是没有。
② ROIC < WACC → 得分硬上限 45（等级封顶「无」）。理由：壁垒若真实存在，必然体现在资本回报上。
第 ② 条来自一次实测：早期版本用纯加权计分，类型分 85 + 证据分 15 + 持续性 10 足以把 ROIC 的负分淹没，得出「壁垒宽」而发现里写着「壁垒存疑」—— 自相矛盾。硬上限用来消除这种矛盾。
字段取值评分映射
moat_type技术专利 / 规模成本 / 网络效应 / 牌照 / 品牌 / 客户粘性 / 无85 / 80 / 90 / 75 / 70 / 75 / 10
moat_source具体来源（必须可命名）为空则等级强制「无」
durability_years持续性估计（年）≥5 年 +10；<3 年 −10 并警示
ROIC − WACC资本回报溢价>5pct 优秀；<0 触发硬上限 45
rd_expense_ratio研发费用率 + 与同业对比低于同业时警示可持续性
substitute_count替代方案数量≥3 个 −15 分
evidence可验证证据列表无证据时标注"属叙述性主张，非事实"

四维综合权重

现金流 30% · 壁垒 25% · 行业 25% · 研报 20%
依据：现金流与壁垒是慢变量（决定能不能买），研报与行业是快变量（决定什么时候买、市场怎么看）。慢变量给更高权重，避免被短期预期牵着走。

二、三类信号的定义与输出结构互不重叠

三类信号各自回答一个不同的问题。它们不是三个并列的指标，而是三个不同的职责。

① 监控信号 MonitorSignal
回答：有什么变化需要我知道。
性质：事件驱动 / 阈值告警。不直接产生买卖动作，只改变"观察状态"，进而影响量化信号能否被执行。
字段取值说明
levelinfo warning criticalinfo 仅记录；warning 禁止加仓；critical 暂缓一切动作
trigger文本触发原因，如"财报临近披露""买入假设被证伪"
window文本必须提供 —— 无时间窗则无法排期执行
implication文本这个信号意味着什么动作约束
source文本来源，便于追溯

当前实现的 6 类触发：停牌、买入假设被证伪、财报临近（≤5 天）、接近涨跌停（<1.5%）、数据缺口、阈值待校准。

② 量化信号 QuantSignal
回答：规则说该做什么。
性质：可执行、有明确价位。由确定性代码产生，无解释空间。
字段取值说明
actionentry / wait / block / exit四种，不含"观察""关注"这类模糊词
tier_decidedtrend / momentum / extreme由哪一级信号决定
stop_pricefloat生效止损位（结构位与 ATR 位取更近者）
effective_stop_typestructure / atr / logic哪一条生效
standard_position_pctfloat标准风险预算法结果
worst_case_position_pctfloat制度修正版结果（考虑连续跌停无法成交）

实测差异：科伦药业标准法 8.18% → 制度修正版 3.64%，折减 55.5%。

③ 多因子信号 FactorSignal
回答：这只股票在同类里排第几。
性质：相对比较，不是绝对判断。只影响仓位大小，不影响方向。
字段取值说明
factor_scoresdict四个模块的原始得分
contributionsdict各因子按权重后的贡献值
compositefloat四维加权综合分
percentilefloat分位 = 有多少同业低于你 ÷ 样本数
layerQ1–Q5Q1 前 20% · Q2 20–40% · Q3 40–60% · Q4 60–80% · Q5 后 20%

未提供同业样本时，以绝对分近似分位，并须显式标注为近似。

三、信号类型 → 操作建议 的对应关系核心

三类信号可能互相矛盾。因此必须先定优先级，再谈映射 —— 否则"多因子好但趋势空头"这类情形无法裁决。

3.1 优先级（决定权从高到低）

序决定者为什么在这个位置
①逻辑止损（基本面证伪）它回答"我为什么买它还成立吗"，是原因层；其余信号都在回答"现在该做什么"，是动作层。原因不成立时，动作层无意义
②量化信号 BLOCK / EXIT确定性的，不含主观判断，必须优先于需要解释的信号
③监控信号 critical暂缓一切加仓动作（但不强制平仓 —— 那是量化的职责）
④多因子分层它衡量的是相对位置。一家排前 10% 的公司也可能处在下跌趋势中 —— 相对好 ≠ 现在该买
⑤量化信号 ENTRY + 监控降级触发建仓，但监控 warning 会使仓位减半

3.2 空仓时的映射矩阵

量化信号因子分层监控级别 操作建议建议仓位决定者
block任意任意不入场0量化（优先级 ②）
wait任意任意观察0量化（优先级 ②）

entryQ1–Q2warning建仓（半仓）标准仓位 ÷ 2监控（优先级 ⑤ 降级）
entryQ1–Q2critical暂缓建仓0监控（优先级 ③）

3.4 判定链（可审计）

每次给出建议时，引擎都会输出完整判定链。这是为了回答"这个建议是基于什么得出的"：

示例输出（量化 ENTRY + 因子 Q1 + 监控 WARNING）

决定者: 监控信号（优先级 ⑤ 降级）
否决/约束:
  ✗ 监控 WARNING：存在需观察的事件
判定链:
  输入: quant=entry factor=Q1 monitor=warning holding=False
  ① 逻辑止损：未触发
  ② 量化 ENTRY —— 通过，进入仓位判定
  ③ 监控：无 CRITICAL

  ⑤ 监控 WARNING —— 仓位减半

四、复盘涵盖的内容维度执行 / 未执行 双向

复盘分两种情形，因为它们的修正方向完全相反：执行了但结果不好 → 可能计划错（调参数）；该执行时没执行 → 可能手软（调执行机制）。混在一起会得出"系统需要优化"这种无用结论。

4.1 共同维度（两种情形都评）

D1 · 信号一致性
实际动作 vs 三类信号给出的建议是否一致。
判据：建议本就是"不动"时未操作 → 一致（100 分）；建议是建仓/清仓而未操作 → 不一致（0 分）。
D2 · 逻辑验证
买入假设是否被证伪。逐条标注 verified / unverified / falsified。
判据：得分 = 已验证数 ÷ 假设总数。任一证伪即触发逻辑止损（优先级高于价格止损）。
D3 · 数据质量
本轮分析的数据缺口数。每项缺口扣 20 分。
判据：缺口字段不得进入决策；缺口过多时结论不可信，须标注后重跑。
D4 · 事后验证
T+5 / T+20 回看，判断当时动作的对错。
判据：执行后价格反向 = 偏错；未操作后价格上涨 = 错过。窗口未到时返回"待补跑"，不猜。

4.2 情形 A：已执行 —— 额外维度

维度评什么判据与修正动作
A1 执行偏差计划价 vs 实际成交价、时间滞后偏差 ≤1% 可接受；>3% 过大。修正：复核下单方式（限价单 vs 市价单）
A2 仓位合规实际仓位 vs 建议仓位实际/建议 >110% 判超配（放大风险敞口）；<90% 判低配（削弱信号有效性）
A3 成本核算实际成本 vs 假设成本印花税已核验为 0.05% 卖出单边；佣金/过户费/滑点须从对账单回填 —— 否则参数寻优会偏向高频

4.3 情形 B：未操作 —— 额外维度

B1 是本模块最关键的一个维度。未操作必须归因，因为不归因就无法区分"计划错"与"手软"，而两者修正方向相反。
维度归因 / 评什么得分修正方向
B1
未执行归因		 signal_not_triggered
信号未触发		100 正常 —— 建议本就是不动，未操作是正确行为
triggered_not_acted
触发了没执行		0 权限问题 —— 修正方向是执行机制（考虑系统接管下单权限），不是参数。追问：若理由是长期逻辑，那这个理由在下一次触发时是否也成立？永远成立的理由等于没有理由
condition_unmet
条件不满足		50 设计问题 —— 修正方向是执行条件（增加不可成交情形的最坏损失重算），不是纪律。跌停封板时系统同样卖不出去，接管没有意义
missed_monitoring
未跟踪		30 流程问题 —— 把标的加入财报日历与日频监控
B2 信号有效性事后验证：信号与人，谁对0–80 信号正确而未执行 → 强化执行机制；信号偏保守而未执行反而更好 → 复核止损宽度与阈值。
特例：条件不满足时不评判对错，只评判预案是否充分（仓位上限是否已计入不可成交情形）
B3 纪律扣分硬性动作未执行0 硬性动作（如硬止损）未执行 → 直接归零 + 建议系统接管。
例外：客观条件不允许时不适用（不构成纪律问题）

4.4 情绪维度（两种情形共用）

E1 · 情绪标签
每次手动加减仓时打标签：平静 / 贪婪 / 恐惧 / 焦虑 / 不甘 / 从众。
判据：仅"平静"视为一致。情绪主导操作占比 >50% → 建议暂停交易。
为什么单列：这是四维里唯一需要手工输入的维度之一，它决定了系统的自动化上限 —— 不要假装它可以自动算出来。

4.5 三种未执行情形的归因对比

未执行原因归因结论系统接管修正动作
触发了没执行【权限问题】修正方向是执行机制，不是参数是系统接管下单权限
信号未触发【正常】未操作是正确行为否无
条件不满足【设计问题】修正方向是执行条件，不是纪律否用最坏损失重算降低仓位上限

开发中发现并修复的两处设计矛盾

① 壁垒模块：评分与发现自相矛盾。
初版纯加权计分，科伦药业算出 99/100 等级「宽」，但同一份输出的发现里写着"ROIC 低于 WACC，技术优势未转化为资本回报，壁垒存疑"。原因是类型分 85 + 证据分 15 + 持续性 10 把 ROIC 的负分淹没了。
修正：ROIC < WACC 时设硬上限 45。修正后为 45/100 等级「无」，与发现一致。四维综合分从 81.7 降到 66.2。
② 复盘模块：归因与修正动作矛盾。
情形"跌停无法成交"下，归因判定为"设计问题、不是纪律问题"，但修正动作里仍建议"系统接管下单权限"。系统在跌停时同样卖不出去，接管没有意义。
修正：B2/B3 在 condition_unmet 情形下不再建议接管，改为"用最坏损失重算降低仓位上限"。
这两处矛盾的共同点：它们都不会报错，只会让结论失去可信度。这类问题只能靠专门针对"一致性"的测试发现，常规功能测试抓不到。
